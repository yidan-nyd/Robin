# ROBIN AI 交互原则与可复用模式

> 这不是一组视觉组件，而是一套供产品、设计与工程共同执行的行为契约。每个模式都规定触发条件、所需数据、界面状态、系统边界与恢复路径。

## 原则 01｜先呈现证据，再给出建议

AI 对现实世界的判断必须附带可理解的依据。来源不明确、时间过期或状态异常的数据，不得被包装成确定结论。

**最低信息要求**

- 观察对象：哪一株植物或哪个区域；
- 数据来源：摄像头、传感器、用户输入或知识库；
- 观察时间：何时采集，当前是否仍然有效；
- 系统状态：正常、低置信、不可用或待确认；
- 能力边界：系统看到了什么，以及尚不能由此判断什么。

**禁止行为**：只凭作物类别推断病害、缺水或成熟度；把模型分数直接解释为现实世界中的“正确概率”。

## 原则 02｜按风险分配自动化，而非按技术能力炫技

模型能够生成一个动作，不代表产品应该执行它。自动化等级由错误后果、可逆性和用户预期共同决定。

| 风险等级 | 示例 | 系统行为 |
| --- | --- | --- |
| 低 | 保存观察、建立提醒 | 可自动完成，并允许撤销 |
| 中 | 调整浇水计划、移动植物 | 解释依据与影响，获得明确确认 |
| 高 | 药剂处理、可能伤害植物的动作 | 不自动执行，提供信息并建议人工或专业处理 |

## 原则 03｜把判断转化为明确的下一步

每条建议回答四个问题：现在发生了什么；依据是什么；建议做什么；完成后如何判断是否有效。避免只输出“注意养护”“可能需要浇水”等无法执行的语言。

## 原则 04｜控制权必须真实存在

用户能够编辑、拒绝、暂停、撤销并接管。控制入口不能藏在二级设置里；App、语音和机器人必须共享同一任务状态。

## 原则 05｜失败需要可见、可解释、可恢复

系统在无检测、低置信、多目标、数据过期、离线或动作失败时明确停止。它应该告诉用户失败发生在哪里，并给出补拍、选择对象、重新连接或人工检查等恢复方法。

## Pattern 01｜Evidence Card 证据卡片

**目的**：让用户在接受建议前理解系统依据。

**触发**：任何涉及植物状态、趋势或行动建议的输出。

**必需数据**：`subject_id`、`source`、`observed_at`、`status`、`model_version`；模型分数仅在能被正确解释时显示。

**状态**：Loading / Current / Low confidence / Stale / Unavailable。

**界面结构**：观察摘要 → 来源与时间 → 原始证据入口 → 局限说明。

**安全规则**：没有有效观测时不得展示确定性状态词。

**复用范围**：植物诊断、健康设备、家庭监控、环境感知。

## Pattern 02｜AI Recommendation 建议单元

**目的**：把生成式回答转化为可评估、可执行的任务。

**必需字段**：状态解释、证据、建议动作、风险级别、预期结果、检查时间、替代方案。

**状态**：Draft / Requires confirmation / Scheduled / Completed / Rejected / Failed。

**安全规则**：建议不得超出当前硬件和数据能力；执行与解释必须分离记录。

## Pattern 03｜Confirm Before Action 行动前确认

**目的**：在改变现实世界状态之前建立清晰的知情确认。

**触发**：浇水、移动、环境调节或任何不可立即撤销的行为。

**界面结构**：将执行什么 → 作用于谁 → 为什么 → 可能影响 → 取消/确认。

**安全规则**：不能用模糊按钮文案代替动作；超时视为未确认。

## Pattern 04｜Low-confidence Recovery 低置信恢复

**目的**：将“不确定”转化为下一步，而不是错误答案。

**恢复路径**：重新拍摄 → 改善光线/角度 → 选择目标 → 补充信息 → 人工判断。

**安全规则**：不得静默沿用上一条观测；重试次数应有限制。

## Pattern 05｜Human Takeover 人工接管

**目的**：在用户判断与系统建议冲突，或任务超出自动化边界时，完整归还控制权。

**必需行为**：暂停当前动作、保留已发生记录、说明设备当前状态、展示安全的后续选项。

## Pattern 06｜Safe Stop 安全停止

**目的**：设备断连、执行失败、数据异常或约束冲突时进入一致的安全状态。

**跨触点反馈**：机器人停止动作；OLED/灯光显示故障；语音说明原因；App 展示影响、日志与恢复入口。

## 资产化规范

每个模式进入设计系统时，应同时包含：用途、触发条件、必需数据、完整状态、内容规范、无障碍要求、埋点事件、工程接口和至少一个失败案例。复用的判断标准不是“复制了组件”，而是新场景能够沿用同一套证据、风险、控制和恢复逻辑。
